Private network

Your machines,
reachable by name

Invite a machine and it answers as myserver.hop from anywhere, on a private address only your machines can reach. Setting up a VPN should be as easy as SSH or scp, so it is.

No port-forwarding

Machines find each other directly through NAT. When a direct path is blocked, a relay forwards encrypted packets it cannot read, and you can run your own with one flag.

No coordination server

Who is on the network is a document your machines replicate between themselves. Nothing of ours has to be up for your machines to find each other.

The role is the access

You never write firewall rules. Invite someone as a developer and the network already knows what a developer can reach.

Underneath, this is a peer-to-peer VPN. We call one of these networks a warren, and a machine that lives on it a node; you will see both words in the command output.

Put a machine on it

The first machine you install with --host creates the network. Every invite after that grows it.

Invite, join, done

Make an invite on any machine that is already on the network. Install on the new machine with that invite, or redeem it with hop connect if WireHop is already there. The network interface and the name come up on their own; nothing to configure on the router, no DNS to edit.

From then on the tools you already use (SSH, scp, VNC, a browser) reach the machine by name, from any network.

Terminal
# On a machine that's already on your network $ hop invite Invite: eyJ0eX... # On the new machine: install and join in one go $ curl -fsSL https://wirehop.org/install.sh | \ bash -s -- --host --invite eyJ0eX... Joined. You are 100.64.3.12 (laptop.hop) # Now your machines answer by name, from anywhere $ ssh myserver.hop $ scp report.pdf myserver.hop:~ $ open vnc://myserver.hop

Reach the things that can't run WireHop

A printer, a NAS, a camera, a whole home or office LAN. One machine that is on that LAN carries the rest.

One port, like ssh -L

# myserver's port 3000, at localhost:3000 $ hop tunnel myserver 3000 # ...or at localhost:8080 instead $ hop tunnel myserver 8080:3000

Works with a plain client install too, no private network needed. The tunnel ends at the machine's own loopback, so it only reaches services running on that machine.

A whole LAN, through one machine

Put WireHop on one machine that sits on the LAN (a Pi is plenty) and let it advertise the LAN's address range. Every other machine on your network can then reach the printer or the NAS by its ordinary LAN address, from anywhere.

Advertising a route is a one-line setting on the bridging machine. How to set it up, in the docs.
