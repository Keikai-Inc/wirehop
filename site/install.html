Two kinds of machine

The same script installs both. One flag decides which.

Your laptop: a client

$ curl -fsSL https://wirehop.org/install.sh | bash

Reaches the machines you are invited to. No sudo, no background service, no network interface. This is all a laptop needs to shell in, run commands and copy files.

A machine you want to reach: a host

$ curl -fsSL https://wirehop.org/install.sh | bash -s -- --host

Installs an always-on service (needs sudo) so the machine stays reachable across reboots, and puts it on your private network with a name like myserver.hop. Run hop invite on it afterwards to let a machine in.

Every release is also published as plain, signed files.

Where else to get it

  • GitHub Releases: a plain binary per platform, with a .sha256 and an RSA .sig beside each one.
  • A signed and notarized macOS .pkg on the same release.
  • npm: npx -y @wirehop/wirehop, which is also how AI tools usually run it.

Check a download by hand

The installer verifies every download against the release key before it runs anything. To do the same yourself, the key is wirehop-release.pub.

$ shasum -a 256 -c hop-*.sha256 $ openssl dgst -sha256 -verify wirehop-release.pub \ -signature hop-*.sig hop-*
