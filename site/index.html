Why hop?

Existing tools all have tradeoffs. hop was built to eliminate them.

End-to-End Encrypted

TLS 1.3 over QUIC. Your traffic is never decrypted by a relay or third-party service. Keys stay on your machines.

NAT Traversal Built In

Works behind ISP NAT, double NAT, and carrier-grade NAT. No port forwarding or router configuration needed.

Single Binary

One download. No runtime dependencies, no accounts to create. The CLI client needs no daemon; always-on hosts run one. Just run it.

One-Time Invite Links

Share a link or token to grant access. Each invite is single-use and cryptographically verified. No shared passwords.

File Transfer Built In

Copy files with hop cp or sync directories with hop sync. No separate SCP/rsync needed—transfers use the same encrypted P2P connection.

Persistent Sessions

Your shell survives disconnects. If your connection drops, hop reconnects and resumes where you left off — no tmux needed.

Plus remote command execution, encrypted secrets, scheduled automation, and kernel-level sandboxing (macOS Seatbelt / Linux Landlock) — with deeper tooling for fleet management, AI orchestration, and terminal session audit (tap).

Install, invite, connect

Up and running in under a minute — no accounts, no servers, no VPN config.

1 · Install

Run one command on the machine you want to reach. It installs hop and prints a one-time invite.

2 · Invite

Share the invite, or use it yourself. It's single-use and time-limited, and its role decides exactly what the new member can reach.

3 · Connect

Redeem it from your laptop with hop connect — you're in a secure shell. After that, it's just hop <name>.

Your own private network — when you need it

Hop also gives you a peer-to-peer private network. Setting up a VPN should be as easy as SSH or scp — so it is.

What's a warren?

It's your private group of machines. Add a machine to your warren and it's reachable by its hostname (a box named myserver answers at myserver.hop) on a private address only your machines can reach — from anywhere, with no port-forwarding, no VPN appliance, and no coordination server in someone else's cloud.

Then the tools you already use just work — SSH, scp, VNC, anything — with the same ease, simplicity, and reliability as hop.

Joining takes one command

A warren travels in an invite. Generate one on any machine that's already on the warren, hand it to the new machine, and run hop connect <invite>. That's it — the machine picks up its private IP and name.hop address and is instantly reachable by every other member.

The invite is single-use and time-limited, and its role decides exactly what the new member can reach. No accounts, no central server — the warren itself is the source of truth, shared peer-to-peer.

Terminal
# Join the warren with an invite $ hop connect eyJ0eX... Joined. You are 100.64.3.12 (laptop.hop) # Your machines, reachable by hostname from anywhere $ ssh myserver.hop # Copy a file with the tools you already know $ scp report.pdf myserver.hop:~ # Even a desktop — VNC over the private network $ open vnc://myserver.hop

Reach the things that can't run hop

Printers, a NAS, cameras, a smart TV, your whole home network — bridged onto your warren through one machine that's already on it.

One machine bridges the rest

Plenty of devices will never run a VPN. So pick one machine that is on your warren — a home server, a Raspberry Pi, your always-on box — and let it carry the others. Tell it which network to share, and every member of your warren can reach everything on that LAN, by its real address, from anywhere.

One machine routes for the whole subnet — set up the hop way: one command, no config files, no appliance.

Even when the addresses collide

Home and cabin both on 192.168.1.x? That normally breaks a VPN — two devices, same address. hop keeps them straight and routes to the right one, so an overlapping network is just another network.

Access is still gated by role — a bridged device is only reachable by members you've allowed.

Terminal
# On the machine that sits on the LAN you want to share $ hop lan advertise 192.168.1.0/24 Advertising 192.168.1.0/24 to the warren # Or share just one device $ hop lan advertise 192.168.1.50/32 # From any other machine on the warren, reach it directly $ ping 192.168.1.50 $ open http://192.168.1.50 # See what's on offer across the warren $ hop lan ls

Always-on machines

One command turns a machine into a node — a machine that stays on your private network and reachable by name, even across reboots. macOS or Linux.

Always reachable

The installer detects your platform and sets up hop as a native system service that starts at boot and stays on your private network — with a stable private IP and a name.hop address. Ideal for home servers, dev boxes, VPS instances, or any always-on machine.

  • Installs binary to /usr/local/bin/hop
  • Registers a native service (LaunchDaemon on macOS, systemd on Linux)
  • Starts hop host at boot, on your private network with a private IP and a name.hop address
  • Built-in P2P VPN is opt-in — and fail-safe: shell/exec/transfer keep working whether or not it's enabled
  • Automatic restarts on crash
  • Works on macOS (Apple Silicon & Intel) and Linux (x86_64, ARM64, ARMv7)
