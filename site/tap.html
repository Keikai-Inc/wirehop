Terminal Session Audit

See every keystroke,
everywhere

hop-tap is a hop extension that captures every TTY/PTY session on a Linux host using eBPF. Authorized peers get live byte streams, current-screen snapshots, and a full session inventory — through the same authenticated QUIC transport hop already uses for everything else.

Get Started What's Captured

From install to live watch in one curl

Three commands from a fresh Linux box to streaming someone's terminal in real time — gated on hop's existing peer authentication.

Install on the host

Single curl. If hop isn't installed, the script installs it first; if hop is already running, hop-tap registers itself as a plugin.

curl -fsSL https://hop-tap.keik.ai/install.sh | bash

Discover sessions

From any peer that's connected to the host. Sessions are filtered by ownership — admin tier sees everything, others see only their own.

hop myserver tap list

Watch live

Live byte stream from the captured session, replayed on your terminal exactly as the original user sees it — colors, vim, the lot.

hop myserver tap watch 0

What every session yields

Per-session state captured at the kernel level, with full identity attribution.

Live byte stream

Subscribe to a pty index and receive every captured chunk as it arrives. The bytes are kernel-faithful: escape sequences, colors, cursor positioning all flow through unchanged.

Off-screen emulator per session

Each session drives an alacritty terminal model on the daemon side. Full CSI / OSC / SGR semantics, alt-screen tracking, cursor and attribute state — same emulator that powers Alacritty itself.

Owner attribution

Sticky opener_* identity captured at session creation, separate from the per-event writer. A sudo'd command shifts the writer to root but the session is still owned by the human who logged in.

Scope-checked access

Per-peer authorization gates list / snapshot / watch. creator role peers see all sessions; other roles see only sessions they own. Forbidden ptys return the same error as non-existent ones to prevent enumeration.

Lifecycle tracking

Sessions are seeded from /proc at daemon startup so anything already running is known immediately. New sessions are picked up on first pty_write; teardown is signalled by a tty_release_struct kprobe.

Full screen snapshots

One-shot tap snapshot N returns the current screen as a row × column grid — including a deterministic SGR-aware replay of colors, attributes, cursor, and alt-screen state.

Identity built into the protocol

Every captured event carries the writer's uid + gid + comm; every session carries a sticky opener identity. Authorization decisions are decoupled from "who's writing right now."

Sticky opener vs. live writer

The first time the daemon sees a pty, it captures the writer as opener_*. After that, only last_* updates per event. So a peer probing "who owns this session" gets a stable answer that doesn't shift mid-sudo.

Username resolution

getpwuid_r resolves uid → username on the host side; protocol carries both so the client sees alice(1000). None when the uid isn't in the host's /etc/passwd (PID/user namespacing edge cases).

Scope check at every entry

list filters; snapshot refuses with the same error as a missing pty; watch refuses with the same wording on StreamClosed. No way to enumerate other users' sessions.

  • opener_uid sticky for the session's lifetime
  • last_uid updates per event, surfacing privilege transitions
  • creator role bypasses the filter (admin tier)
  • peer role sees only own sessions
  • Same denial wording as missing-pty for non-enumeration

Where it earns its keep

Auditing, AI orchestration, and incident response — same daemon, same protocol.

Live operator audit

Watch what your team is doing on production hosts in real time. The opener identity gives you accurate "who logged in" attribution even across sudo and setpriv. Every byte is faithful.

AI agent supervision

Expose the tap to an MCP-driven AI orchestrator. Claude or another agent can monitor active sessions, summarize activity, flag anomalies, and (eventually) open its own session to investigate or remediate.

Incident response

When something goes wrong, you want the exact bytes the operator typed and saw — not approximate timestamps from shell history. The replay gives you that, with full color and cursor fidelity.

Compliance & review

For environments that require keystroke-level audit trails, hop-tap captures every PTY write at the kernel layer — independent of user-space tooling, immune to shell-history evasion.

Built differently

Pure-Rust eBPF on a CO-RE-aware rustc fork. Same .bpf.o works on every kernel that has the right field names, regardless of layout drift.

CO-RE in pure Rust

The kernel-side program is built with vlad's #[relocatable] rustc fork — field offsets are patched by aya at load time against the running kernel's BTF. We've validated the same binary on Linux 5.4 and 6.8 with no recompile, despite a 256-byte offset drift between them.

pty_write, not tty_write

We hook pty_write, where the kernel has already flattened any iov_iter into a contiguous buffer. One bpf_probe_read_kernel and we have the bytes — no segment walking, no union-discriminant gymnastics.

Same QUIC transport

Tap traffic flows over hop's existing iroh-net QUIC connections. Same auth, same NAT-traversal, same encryption — no new sockets, no separate certificate, no new firewall rules.

Plugin architecture

hop-tap is a hop extension — a separate daemon that registers via a manifest in /etc/hop/extensions/. The hop daemon discovers it, dispatches authenticated peer requests, and relays multi-frame stream responses over the same QUIC pipe.

Install

One curl. Auto-handles the hop dependency.

Run the installer

If hop isn't installed, the script bootstraps it first. If hop is already running, hop-tap registers itself as a plugin and starts.

curl -fsSL https://hop-tap.keik.ai/install.sh | bash

Verify the daemon

Systemd unit hop-tap.service runs as root (eBPF needs privileged caps).

sudo systemctl status hop-tap

List sessions

From any peer with hop access to the host. The extension shows up in hop ext list as well.

hop <host> tap list

Watch live

Live byte streaming over the same QUIC connection hop already uses. Your terminal renders the captured session natively.

hop <host> tap watch <pty>

Audit terminals on your fleet

hop-tap is Linux-only (eBPF). Install on a server, then run hop <host> tap watch from any client OS — macOS, Windows, Linux.
